## English

Bug-fix release of **Digimon World 4 — Recomp**, a native Linux port of Digimon World 4 (original Xbox, 2005) made by static recompilation. No emulator. Still early and experimental.

> ⚠️ **No game files included.** You need your own, legally obtained Digimon World 4 disc for the Xbox, **NTSC-U** (title ID `42410002`). Never share game files.

> **Linux only, for now.** The Windows and macOS ports have not been started; both are planned.
> **Only the beginning of the game has been tested:** Terminal Area (the lobby), Central Area, Death Valley and Humid Cave.

**If you have v0.3.0 or older, update.** Those versions lose the picture after a few minutes of normal play.

### What is fixed

- **The screen turned completely white after a few minutes**, typically when changing areas (for example saving and going back to the Central Area). The game keeps its textures and geometry in 64 MB of memory, freeing the old area's and loading the new one's at every area change; the freed memory was never given back, so after several changes there was none left and nothing could be drawn. Freed memory is now reused. In the lobby the memory in use went from 22 MB to 8.5 MB. This bug was in every earlier release.

Everything else is the same as in [v0.3.0](https://github.com/lorransouzaaguiar/Digimon-World-4-Recomp/releases/tag/v0.3.0), whose notes list the new features and the known issues.

### Getting started

1. Download `DigimonWorld4-Recomp-v0.3.1-x86_64.AppImage` below.
2. Make it executable (`chmod +x DigimonWorld4-Recomp-*.AppImage`) and open it.
3. On the **Play** screen, choose the image (`.iso`) of your disc, or a folder with the disc already extracted.
4. Click **PLAY**.

**Requirements:** Linux x86-64, glibc 2.38 or newer (Ubuntu 24.04+, Fedora 39+, Arch, SteamOS 3.6+), a GPU with a working **Vulkan or OpenGL 3.3** driver. If the AppImage does not start because FUSE is missing, run it with `--appimage-extract-and-run`, or use the `.tar.gz` (same content: unpack and run `./DigimonWorld4-Recomp`).

Saves, settings and logs are kept in `~/.local/share/dw4-recomp/`. Saves from earlier versions keep working.

### Tested

On one machine only (NVIDIA GeForce RTX 5070, AMD Ryzen 7 5700X, CachyOS Linux): the automated run from boot to the lobby matches the reference frames on Vulkan and on OpenGL, and the fix was confirmed in play. A long session with many area changes has not been measured after the fix.

### Known issues

- This fix changes where the game's memory blocks are placed, which could expose a bug that was hidden before. If the game starts crashing where it did not, start it with `DW4_NO_HEAP_RECLAIM=1` to go back to the old behaviour, and report it.
- All the known issues of v0.3.0 still apply: the floor that darkens for a moment (less with OpenGL), the possible quit when skipping the intro movie, the stretched loading screen in widescreen, and that only the first areas, one player and one machine were tested.

### Reporting a problem

In the launcher, open **Support → Create report** and attach the text file to an issue. Do not attach game files.

### Checksums

`SHA256SUMS-v0.3.1.txt` lists the SHA-256 of both downloads.

## Português (Brasil)

Release de correção do **Digimon World 4 — Recomp**, um port nativo para Linux de Digimon World 4 (Xbox original, 2005) feito por recompilação estática. Não é um emulador. Ainda inicial e experimental.

> ⚠️ **Os arquivos do jogo não vêm junto.** Você precisa do seu próprio disco de Digimon World 4 para Xbox, obtido legalmente, versão **NTSC-U** (title ID `42410002`). Nunca compartilhe arquivos do jogo.

> **Por enquanto, só Linux.** Os ports para Windows e macOS ainda não foram começados; os dois estão planejados.
> **Só o começo do jogo foi testado:** Terminal Area (o lobby), Central Area, Death Valley e Humid Cave.

**Se você tem a v0.3.0 ou anterior, atualize.** Essas versões perdem a imagem depois de alguns minutos de jogo normal.

### O que foi corrigido

- **A tela ficava toda branca depois de alguns minutos**, em geral ao trocar de área (por exemplo, salvar e voltar para a Central Area). O jogo guarda texturas e geometria em 64 MB de memória, liberando as da área antiga e carregando as da nova a cada troca; a memória liberada nunca era devolvida, então depois de algumas trocas não sobrava nenhuma e nada mais podia ser desenhado. Agora a memória liberada é reaproveitada. No lobby, a memória em uso foi de 22 MB para 8,5 MB. O defeito existia em todos os releases anteriores.

Todo o resto é igual à [v0.3.0](https://github.com/lorransouzaaguiar/Digimon-World-4-Recomp/releases/tag/v0.3.0), cujas notas trazem as novidades e os problemas conhecidos.

### Como começar

1. Baixe `DigimonWorld4-Recomp-v0.3.1-x86_64.AppImage` abaixo.
2. Torne o arquivo executável (`chmod +x DigimonWorld4-Recomp-*.AppImage`) e abra.
3. Na tela **Jogar**, escolha a imagem (`.iso`) do seu disco, ou uma pasta com o disco já extraído.
4. Clique em **JOGAR**.

**Requisitos:** Linux x86-64, glibc 2.38 ou mais nova (Ubuntu 24.04+, Fedora 39+, Arch, SteamOS 3.6+) e placa de vídeo com driver **Vulkan ou OpenGL 3.3** funcionando. Se o AppImage não abrir por falta de FUSE, rode com `--appimage-extract-and-run` ou use o `.tar.gz` (mesmo conteúdo: extraia e rode `./DigimonWorld4-Recomp`).

Saves, opções e logs ficam em `~/.local/share/dw4-recomp/`. Os saves das versões anteriores continuam valendo.

### Testado

Em uma única máquina (NVIDIA GeForce RTX 5070, AMD Ryzen 7 5700X, CachyOS Linux): o percurso automático do boot ao lobby confere com os quadros de referência em Vulkan e em OpenGL, e a correção foi confirmada jogando. Uma sessão longa com muitas trocas de área não foi medida depois da correção.

### Problemas conhecidos

- A correção muda onde ficam os blocos de memória do jogo, o que pode expor um defeito que antes estava escondido. Se o jogo passar a fechar onde não fechava, abra-o com `DW4_NO_HEAP_RECLAIM=1` para voltar ao comportamento antigo, e relate.
- Continuam valendo todos os problemas conhecidos da v0.3.0: o chão que escurece por um instante (menos com OpenGL), o possível fechamento ao pular o vídeo de abertura, a tela de loading esticada em widescreen, e o fato de só as primeiras áreas, um jogador e uma máquina terem sido testados.

### Relatar um problema

No launcher, abra **Suporte → Gerar relatório** e anexe o arquivo de texto a uma issue. Não anexe arquivos do jogo.
