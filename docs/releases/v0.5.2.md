## English

**Fixes updating from the launcher on Windows, and the window icon.** This is a release of **Digimon World 4 — Recomp**, a native port of Digimon World 4 (original Xbox, 2005) made by static recompilation. No emulator. Still early and experimental.

> ⚠️ **No game files included.** You need your own, legally obtained Digimon World 4 disc for the Xbox, **NTSC-U** (title ID `42410002`). Never share game files.

> **Only the beginning of the game has been tested:** Terminal Area (the lobby), Central Area, Death Valley and Humid Cave.

### What changed

**Windows**

- **"Update now" failed** going from v0.5.0 to v0.5.1 with "Could not write the update: [Errno 2] No such file or directory". The package carried four unused files with very long names; unpacked in the update folder, their full path went past Windows' 260-character limit. Nothing was installed when it failed. Those files are gone from the package, the updater now copes with long paths, and the package build refuses long names from now on.
- **The window and taskbar icon** was the generic one. The launcher and the game now show the project's icon.
- When an update fails, the launcher now also shows the button that opens the download page.

**Linux**

- The launcher window now has the project's icon. Nothing else changed: the game is the same as v0.5.1.

### Updating

- **Windows, from v0.5.0 or v0.5.1:** open the launcher and use **Update now** on the **Play** screen. This is the path this release repairs, and it has only been run under Wine, not on real Windows. If it fails, download the `.zip` below and extract it as usual (saves and settings are kept), and please report it.
- **Linux AppImage, from v0.5.0 or v0.5.1:** **Update now** on the **Play** screen. The Linux `.tar.gz` only opens this page.
- **From v0.4.1 or earlier:** download the package below; those versions cannot update themselves.

Saves and settings are kept (`~/.local/share/dw4-recomp/` on Linux, `%APPDATA%\dw4-recomp\` on Windows).

### Getting started

- **Windows:** download `DigimonWorld4-Recomp-v0.5.2-windows-x86_64.zip`, extract all of it, open `DigimonWorld4-Recomp.exe` (SmartScreen: **More info → Run anyway**), choose the image (`.iso`) of your disc and click **PLAY**. Windows 10 or 11, 64-bit, a GPU with a Vulkan or OpenGL 3.3 driver.
- **Linux:** download `DigimonWorld4-Recomp-v0.5.2-x86_64.AppImage`, make it executable (`chmod +x`), open it, choose the image (`.iso`) of your disc and click **PLAY**. x86-64, glibc 2.38 or newer, a GPU with a Vulkan or OpenGL 3.3 driver. Without FUSE: `--appimage-extract-and-run`, or the `.tar.gz`.

### Tested

- **Real Windows 11:** the `.zip` of this release was opened and the icon is right. Earlier the same day, on that machine, the launcher of v0.5.0 found v0.5.1, downloaded it and checked it before failing at the long path.
- **Under Wine:** the published v0.5.1 updating itself to this package (version changed, a user file in the folder kept); the new updater unpacking and copying the old package through paths of 398 characters; boot to the lobby matching the reference frames.
- **Linux:** the AppImage's self-test.

### Known issues

- **The update on real Windows is still unconfirmed** (see "Updating"). On Windows, if copying the new files fails half way there is no rollback: the launcher tells you to download the package by hand.
- Everything listed for [v0.5.0](https://github.com/lorransouzaaguiar/Digimon-World-4-Recomp/releases/tag/v0.5.0) still applies: more than one controller untested, the floor that darkens for a moment, and the possible quit when skipping the intro movie with START.

### Reporting a problem

In the launcher: **Support → Create report**, and attach the file to an issue at https://github.com/lorransouzaaguiar/Digimon-World-4-Recomp/issues. The report has no game files and not your home folder's name.

### Checksums

`SHA256SUMS-v0.5.2.txt` lists the SHA-256 of the three downloads.

**Windows**

- **"Atualizar agora" falhava** da v0.5.0 para a v0.5.1 com "Não foi possível gravar a atualização: [Errno 2] No such file or directory". O pacote trazia quatro arquivos sem uso com nomes muito longos; extraídos na pasta da atualização, o caminho completo passava do limite de 260 caracteres do Windows. **Linux**
