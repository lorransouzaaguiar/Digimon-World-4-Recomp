## English

Third release of **Digimon World 4 — Recomp**, a native Linux port of Digimon World 4 (original Xbox, 2005) made by static recompilation. No emulator. Still early and experimental.

> ⚠️ **No game files included.** You need your own, legally obtained Digimon World 4 disc for the Xbox, **NTSC-U** (title ID `42410002`). Never share game files.

> **Linux only, for now.** The Windows and macOS ports have not been started; both are planned.
> **Only the beginning of the game has been tested:** Terminal Area (the lobby), Central Area, Death Valley and Humid Cave.

### Getting started

1. Download `DigimonWorld4-Recomp-v0.3.0-x86_64.AppImage` below.
2. Make it executable (`chmod +x DigimonWorld4-Recomp-*.AppImage`) and open it.
3. On the **Play** screen, choose the image (`.iso`) of your disc, or a folder with the disc already extracted.
4. Click **PLAY**.

Nothing else has to be installed: the launcher, Qt, SDL2 and the other libraries are inside the file.

**Requirements:** Linux x86-64, glibc 2.38 or newer (Ubuntu 24.04+, Fedora 39+, Arch, SteamOS 3.6+), a GPU with a working **Vulkan or OpenGL 3.3** driver. Vulkan needs the system's Vulkan loader (`libvulkan.so.1`, installed with any Vulkan driver); without it the game starts with OpenGL. If the AppImage does not start because FUSE is missing, run it with `--appimage-extract-and-run`, or use the `.tar.gz` (same content: unpack and run `./DigimonWorld4-Recomp`).

Saves, settings and logs are kept in `~/.local/share/dw4-recomp/`. Saves from earlier versions keep working.

### What is new

**Performance**

- **Much lower processor use.** Two threads used to spin while waiting for the next frame; they now sleep. On the test machine the lobby went from about two busy cores to about a third of one. This matters most on laptops and on processors with few cores.
- **Vulkan now presents straight from the graphics card.** The finished frame is no longer copied back through memory to reach the window. Areas that ran at 34–50 fps at 1440p and 4K now hold 60 fps on the test machine.
- **Experimental parallel mode** (*Graphics → Performance*, off by default): game logic and drawing run on two cores at the same time instead of taking turns. Meant for slower processors; on the test machine it makes no visible difference.

**Widescreen (16:9 and 21:9)**

- The **player panel** (portrait, HP/MP, level) and the **minimap** now sit in the screen corners instead of in a 4:3 column in the middle.
- **Fades and dimming cover the whole screen.** Changing areas used to show a dark 4:3 square with the scenery still visible at the sides.
- The **16:10** option was removed. A saved 16:10 setting becomes 16:9.

**Fixes**

- **The stage minimap was drawn enormous**, covering half the screen, at any aspect ratio. It is back to a small square in the top-right corner.

**Launcher**

- *Graphics* reordered: graphics API, picture, window, performance. The window opens larger and the scroll bar is always visible when there is more below.
- The **CPU** graphics option was removed; the choices are Vulkan and OpenGL.
- *Support* gained a "If the game is slow" list, and the problem report now includes the processor and a frame-rate summary of the session.

### Tested on

One machine only: NVIDIA GeForce RTX 5070 (12 GB), AMD Ryzen 7 5700X, 32 GB RAM, CachyOS Linux.

- Menus, Digimon creation and the lobby: 60 fps from 480p to 4K on Vulkan (limit set to 60).
- Central Area and the first stages: 60 fps at 2560×1440 and at 4K, as played.
- Processor use in the lobby at 480p: 28% of one core (it was 195%).
- The minimap was checked at 4:3, 16:9 and 21:9; the player panel with one player.

### Known issues

- The floor sometimes darkens for a fraction of a second in some areas (Central Area, caves). Cosmetic; the cause has not been found. In play it showed up less with **OpenGL** than with Vulkan, so switching the graphics API is worth trying if it bothers you; OpenGL is slower at 1440p and above.
- Skipping the intro movie with START can make the game quit. In automated runs without a window it happened in 2 of 16; it was not seen when playing in a window. Start the game again.
- In widescreen the loading screen is stretched to the full width. The selection bar of the quick item menu was fixed but has not been confirmed in play.
- **F12** (save the last seconds of frames) is now off by default, because it forced every frame to be copied back. Start the game with `DW4_FRAME_RING=1` to turn it on. **F9** still saves a screenshot.
- At 60 fps the game runs twice as fast as on the console, because its logic advances per frame. The default is 30.
- Automatically generated reflections and shine are not implemented; some objects may look flat.
- Only the first areas were played. Later areas, bosses and multiplayer (2–4 players) are untested.
- Tested on one machine. AMD and Intel graphics, slower processors, other distributions and drivers are untested, and so is reading a real disc image with the built-in reader: if it fails, extract the disc with [extract-xiso](https://github.com/XboxDev/extract-xiso) and choose the folder.

### Reporting a problem

In the launcher, open **Support → Create report** and attach the text file to an issue. For a picture glitch, switch to OpenGL if you can, press **F9** with the glitch on screen and attach what it saves in `~/.local/share/dw4-recomp/shots/`. Do not attach game files.

## Português (Brasil)

Terceiro release do **Digimon World 4 — Recomp**, um port nativo para Linux de Digimon World 4 (Xbox original, 2005) feito por recompilação estática. Não é um emulador. Ainda inicial e experimental.

> ⚠️ **Os arquivos do jogo não vêm junto.** Você precisa do seu próprio disco de Digimon World 4 para Xbox, obtido legalmente, versão **NTSC-U** (title ID `42410002`). Nunca compartilhe arquivos do jogo.

> **Por enquanto, só Linux.** Os ports para Windows e macOS ainda não foram começados; os dois estão planejados.
> **Só o começo do jogo foi testado:** Terminal Area (o lobby), Central Area, Death Valley e Humid Cave.

### Como começar

1. Baixe `DigimonWorld4-Recomp-v0.3.0-x86_64.AppImage` abaixo.
2. Torne o arquivo executável (`chmod +x DigimonWorld4-Recomp-*.AppImage`) e abra.
3. Na tela **Jogar**, escolha a imagem (`.iso`) do seu disco, ou uma pasta com o disco já extraído.
4. Clique em **JOGAR**.

Não é preciso instalar mais nada: o launcher, o Qt, a SDL2 e as outras bibliotecas estão dentro do arquivo.

**Requisitos:** Linux x86-64, glibc 2.38 ou mais nova (Ubuntu 24.04+, Fedora 39+, Arch, SteamOS 3.6+) e placa de vídeo com driver **Vulkan ou OpenGL 3.3** funcionando. O Vulkan precisa do carregador do sistema (`libvulkan.so.1`, que vem com qualquer driver Vulkan); sem ele o jogo abre com OpenGL. Se o AppImage não abrir por falta de FUSE, rode com `--appimage-extract-and-run` ou use o `.tar.gz` (mesmo conteúdo: extraia e rode `./DigimonWorld4-Recomp`).

Saves, opções e logs ficam em `~/.local/share/dw4-recomp/`. Os saves das versões anteriores continuam valendo.

### O que há de novo

**Desempenho**

- **Uso de processador muito menor.** Duas threads ficavam girando à espera do próximo quadro; agora dormem. Na máquina de teste o lobby foi de cerca de dois núcleos ocupados para cerca de um terço de um. Pesa mais em notebooks e em processadores com poucos núcleos.
- **O Vulkan agora apresenta direto pela placa de vídeo.** O quadro pronto não é mais copiado de volta pela memória para chegar à janela. Áreas que rodavam a 34–50 fps em 1440p e 4K agora seguram 60 fps na máquina de teste.
- **Modo paralelo experimental** (*Gráficos → Desempenho*, desligado por padrão): a lógica do jogo e o desenho rodam em dois núcleos ao mesmo tempo, em vez de se revezarem. Feito para processadores mais fracos; na máquina de teste não faz diferença visível.

**Widescreen (16:9 e 21:9)**

- O **painel do jogador** (retrato, HP/MP, nível) e o **minimapa** agora ficam nos cantos da tela, e não numa coluna 4:3 no meio.
- **Fade e escurecimento cobrem a tela inteira.** Ao trocar de área aparecia um quadrado 4:3 escuro com o cenário ainda visível nas laterais.
- A opção **16:10** foi removida. Uma configuração salva com 16:10 vira 16:9.

**Correções**

- **O minimapa das fases era desenhado enorme**, cobrindo metade da tela, em qualquer proporção. Voltou a ser um quadrado pequeno no canto superior direito.

**Launcher**

- *Gráficos* reordenado: API gráfica, imagem, janela, desempenho. A janela abre maior e a barra de rolagem fica sempre visível quando há mais conteúdo abaixo.
- A opção gráfica **CPU** foi removida; as escolhas são Vulkan e OpenGL.
- *Suporte* ganhou uma lista "Se o jogo estiver lento", e o relatório de problema agora inclui o processador e um resumo dos quadros por segundo da sessão.

### Testado em

Uma única máquina: NVIDIA GeForce RTX 5070 (12 GB), AMD Ryzen 7 5700X, 32 GB de RAM, CachyOS Linux.

- Menus, criação do Digimon e lobby: 60 fps de 480p a 4K em Vulkan (limite em 60).
- Central Area e primeiras fases: 60 fps em 2560×1440 e em 4K, jogando.
- Uso de processador no lobby em 480p: 28% de um núcleo (eram 195%).
- O minimapa foi conferido em 4:3, 16:9 e 21:9; o painel do jogador, com um jogador.

### Problemas conhecidos

- O chão às vezes escurece por uma fração de segundo em algumas áreas (Central Area, cavernas). É cosmético; a causa não foi encontrada. Jogando, apareceu menos com **OpenGL** do que com Vulkan, então vale trocar a API gráfica se isso incomodar; o OpenGL é mais lento de 1440p para cima.
- Pular o vídeo de abertura com START pode fechar o jogo. Nos testes automáticos sem janela aconteceu em 2 de 16 execuções; jogando com janela não foi visto. Abra o jogo de novo.
- Em widescreen a tela de loading fica esticada na largura toda. A barra de seleção do menu rápido de itens foi corrigida, mas ainda não foi confirmada jogando.
- **F12** (gravar os últimos segundos de quadros) agora vem desligado, porque obrigava a copiar todo quadro de volta. Abra o jogo com `DW4_FRAME_RING=1` para ligar. **F9** continua gravando uma captura de tela.
- A 60 fps o jogo roda duas vezes mais rápido que no console, porque a lógica dele avança por quadro. O padrão é 30.
- Reflexos e brilhos gerados automaticamente não estão implementados; alguns objetos podem parecer chapados.
- Só as primeiras áreas foram jogadas. Áreas seguintes, chefes e multijogador (2 a 4 jogadores) não foram testados.
- Testado em uma única máquina. Placas AMD e Intel, processadores mais fracos, outras distribuições e drivers não foram testados, nem a leitura de uma imagem de disco real pelo leitor embutido: se falhar, extraia o disco com o [extract-xiso](https://github.com/XboxDev/extract-xiso) e escolha a pasta.

### Relatar um problema

No launcher, abra **Suporte → Gerar relatório** e anexe o arquivo de texto a uma issue. Para um defeito de imagem, troque para OpenGL se puder, aperte **F9** com o defeito na tela e anexe o que ele grava em `~/.local/share/dw4-recomp/shots/`. Não anexe arquivos do jogo.
